## SPRINT HYDRATION-FIX-4 — shipped (commit `13eb001`)

The realtime-js bundle was still being evaluated because four chrome components in the shared `(member)/layout.tsx` (directly or via subtree imports) load `@/lib/supabase/client` at module init.

### Suspects (all import `@/lib/supabase/client` directly or transitively)
| Component | Realtime path |
|---|---|
| `TopNav` | imports `createClient` directly; subtree `NotifBell → NotifDrawer` also imports |
| `BottomTabBar` | subtree `MoreDrawer` imports `createClient` |
| `NextEventBanner` | imports `createClient` directly |
| `RightRail` | imports `createClient` directly |

`@/lib/supabase/client` → `@supabase/supabase-js` → `@supabase/realtime-js`. The realtime library's module init wires up MessagePort plumbing that lands inside React's hydration commit and trips #425.

### Files
- **`apps/web/components/layout/MemberChromeClient.tsx`** (NEW, `'use client'`) — exports `TopNavClient`, `BottomTabBarClient`, `NextEventBannerClient`, `RightRailClient`, each `dynamic(() => import(...), { ssr: false })`. Exports the dynamic components directly (no prop-forwarding wrappers) so the imported component types flow through unchanged.
- **`apps/web/app/(member)/layout.tsx`** — both branches (dev_session bypass and the regular Supabase path) updated to use the four `*Client` wrappers. Structural `<div>`s and `<main>` stay server-rendered.

### Outcome
