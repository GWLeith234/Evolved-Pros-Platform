## SPRINT V-CHECKOUT — shipped (commit `a78e315`)

Replaced the storefront link flow (which required Vendasta Business App
signup) with a server-side `/api/checkout` endpoint that creates an Account
Group, submits an order via `/platform/orders`, and redirects to the hosted
payment URL from the response.

### Files
- **`supabase/migrations/047_vendasta_account_group_id.sql`** — adds
  `public.users.vendasta_account_group_id` column + partial index. Applied
  to remote project `udbwrapkshfjkctylbmm`. Renumbered from spec's `044`
  because 044/045/046 were already taken.
- **`apps/web/lib/vendasta/auth.ts`** — `client_credentials` OAuth2 token
  fetch against `https://sso-api-prod.apigateway.co/oauth2/token` using
  `VENDASTA_CLIENT_ID` + `VENDASTA_CLIENT_SECRET`. Module-level 1hr cache.
  Distinct from the existing `oauth.ts` JWT-bearer flow.
- **`apps/web/lib/vendasta/accounts.ts`** — `getOrCreateAccountGroup`:
  reads AGID from `public.users`, creates an Account Group via
  `POST /platform/salesAccounts` if null, persists the AGID back via
  `adminClient`.
- **`apps/web/lib/vendasta/orders.ts`** — `createOrder`: POSTs
  `/platform/orders` with the AGID + a single line item, logs the full
  response, scans candidate fields (`paymentUrl`, `payment_url`,
  `checkoutUrl`, `checkout_url`, `hostedPaymentUrl`, `hosted_payment_url`,
  `url`, `data.links.payment`, `data.links.checkout`, `data.links.self`)
  for the hosted payment URL. Throws **"No payment URL in Vendasta order
  response — inspect logs"** when none match.
- **`apps/web/app/api/checkout/route.ts`** — auth-gated POST. Allowlists
  the SKU against the four `VENDASTA_*_SKU` env vars. Returns
  `{ paymentUrl }` or `{ error }`.
- **`apps/web/app/(public)/pricing/page.tsx`** + new
  **`PricingCtaButton.tsx`** — replaced anchor hrefs (`#vendasta-vip`,
  `#vendasta-pro`) with onClick handlers that POST to `/api/checkout`.
  401 → `/login?redirect=/pricing`.
- **`apps/web/app/membership/MembershipPageClient.tsx`** — replaced direct
  `NEXT_PUBLIC_VENDASTA_CHECKOUT_URL?sku=` link with `/api/checkout` call.
  SKUs now sourced from `NEXT_PUBLIC_VENDASTA_*_SKU` env vars (server
  validates against the non-public copies).
- **`apps/web/lib/vendasta/sku-mapping.ts`** — env-var lookup now wins over
  the legacy pattern matcher, so the opaque `MP-{hash}` marketplace SKUs
  the webhook receives route to the correct tier.
- **`packages/db/types.ts`** — added `vendasta_account_group_id` to the
  users table Row / Insert / Update types.

## SPRINT HYDRATION-FIX-2 — halted, no commit

User asked to kill React #425 / #422 on `/community` and `/events`.
Hypothesis in the spec: a Supabase realtime channel or `BroadcastChannel`
is being created at render scope (outside `useEffect`), causing

this.

### Sweep findings — hypothesis is wrong
- `grep -rn "BroadcastChannel\|MessageChannel\|MessagePort"` across
  `apps/web/` → **zero hits**. The `MessagePort.M` in the stack trace is
  React 18's scheduler internal (`requestHostCallback` uses
  `MessageChannel`), not application code.
- All `.channel(` / `supabase.channel(` calls (`CommunityFeed.tsx:53`,
  `UnifiedCommunityPage.tsx:129`, `ConversationThread.tsx:68/96`,
  `NextEventBanner.tsx:27` indirectly, `RightRail.tsx:21` indirectly) are
  inside `useEffect` with proper cleanup.
- All direct children of `(member)/layout.tsx` (`TopNav`, `BottomTabBar`,
  `NextEventBanner`, `RightRail`, `EpisodeBanner`, `ToastProvider`,
  `AskGeorgeDrawer`) have every `new Date()` / `Date.now()` /
  `Math.random()` / `document.*` / `localStorage` call inside a
  `useEffect` or event handler. None at render scope.

### Remaining unfixed locale leaks — confirmed not on affected paths
- `PollCard.tsx:97,136` — `toLocaleDateString('en-US')` without UTC.
  But `grep -rn "from.*PollCard"` → 0 importers. Dead code.

  `CommunityLayout`, which is the legacy `/community/[channelSlug]` per-
  channel view, NOT the unified `/community` feed that errors.
