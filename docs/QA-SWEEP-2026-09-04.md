### S1 — Paid curriculum readable via RLS

**Files:** `packages/db/migrations/001_initial_schema.sql` (lines 244–248); `apps/web/lib/academy/fetchers.ts`; `apps/web/app/api/lessons/[lessonId]/mux-token/route.ts`

**What:** `lessons_select_authenticated` / `courses_select_authenticated` allow any `authenticated` role to `SELECT` published lessons and courses. Comment in schema: "tier enforcement in app layer." App-layer gates (page redirect, nulling `mux_playback_id`, mux-token 403) are real. Mux playback is signed (`playback_policy: ['signed']` + `generateMuxToken`), so **video does not stream** from a stolen playback id alone.

**Why it matters:** A free Community member with the browser anon key can still read `transcript`, `description`, and other lesson columns for VIP/Pro pillars. That is paid text curriculum.

**Fix (hypothesis):** Split lesson metadata vs body (view for title/duration/thumbnail; RLS on body/transcript that joins `courses.required_tier` to the caller's effective tier), **or** a `SECURITY DEFINER` function used only by the app. Keep mux-token fail-closed. **Effort: L**

### S1 — `public.users` wide SELECT for every logged-in member

**Files:** `packages/db/migrations/001_initial_schema.sql` (199–202); `supabase/migrations/024_tier_rename_and_keynote.sql` (`GRANT SELECT, UPDATE ON public.users TO authenticated`); `supabase/migrations/065_users_stripe_columns.sql`; `supabase/migrations/081_lock_down_users_grants_and_definer_rpcs.sql`

**What:** 081 revoked **anon** SELECT (good; prior S1). Authenticated still has table-level SELECT. Policy `users_select_authenticated` is `USING (auth.role() = 'authenticated')` with no column restriction. Stripe customer/subscription ids, email, role, `access_status`, Vendasta ids sit on the same table.

**Why it matters:** Any member can enumerate the member list and billing identifiers from the browser client. Directory/community legitimately need display name + avatar + tier, not email or Stripe ids.

**Fix (hypothesis):** Replace the open SELECT with a `public.member_directory` view (safe columns only) and `SELECT` policy `auth.uid() = id` (plus admin) on `users`. Confirm no client query still does `from('users').select('*')`. **Effort: L**

### S1 — Published events expose join/recording URLs without a tier check

**Files:** `packages/db/migrations/001_initial_schema.sql` (233–234); `apps/web/app/api/events/[eventId]/route.ts` (app-layer `hasTierAccess`)

**What:** `events_select_authenticated` is published-only, not tier-aware. Columns include `zoom_url` and `recording_url`. APIs strip or gate those after the fact.

**Why it matters:** A below-tier member can read Pro/keynote join links and recordings directly from PostgREST.

**Fix (hypothesis):** RLS that hides `zoom_url` / `recording_url` unless the viewer meets `required_tier` (column-privileged view, or two tables). Do not rely on the API mapper. **Effort: M**

### S2 — Pinned community HTML is unsanitized; members can UPDATE `is_pinned`

**Files:** `apps/web/components/community/PinnedPost.tsx` (23–26); `apps/web/components/community/UnifiedCommunityPage.tsx` (313); `packages/db/migrations/001_initial_schema.sql` (213–214 `posts_update_own`)

**What:** Regular post bodies render as text (`PostCard.tsx`). Pinned announcements run `dangerouslySetInnerHTML` after only a `**bold**` replace. `posts_update_own` does not exclude `is_pinned`. `fetchPinnedAnnouncement` takes the latest `is_pinned = true` row via service role.

**Why it matters:** Hypothesis: a member can `UPDATE` their own post `{ is_pinned: true, body: '<img onerror=…>' }` and XSS every community viewer (including admins). Not confirmed against live policies if production drifted from 001.

**Fix (hypothesis):** (1) Escape, then allow `<strong>` only, or drop HTML. (2) Trigger or RLS: only `role = admin` may set `is_pinned` / `post_type = announce`. **Effort: M**

### S3 — Stripe success/cancel URLs hit a 308 with no UI handler

**Files:** `apps/web/app/api/stripe/checkout/route.ts` (111–112); `apps/web/next.config.mjs` (`/membership` → `/pricing`); `apps/web/app/(public)/pricing/page.tsx` (ignores `checkout`)

**What:** Checkout returns to `/membership?checkout=success|cancelled`. Config 308s to `/pricing` (query typically preserved). Pricing never reads `checkout`.

**Why it matters:** Access still depends on the webhook (signature-verified). The buyer gets no success or cancel state. If a proxy ever drops the query, it is just a silent `/pricing`.

**Fix (hypothesis):** `success_url` / `cancel_url` → `/pricing?checkout=…` and a small banner on that param. Add a webhook unit test. **Effort: M**

### S3 — Public write endpoints weakly rate-limited

**Files:** `apps/web/app/api/ads/events/route.ts` (no auth/limit); `apps/web/app/api/welcome/claim/route.ts`; `apps/web/app/api/guest/upload/route.ts`; speaking/book in-memory limiters (reset per instance)

**What:** Ads events are unauthenticated service-role writes. Welcome claim returns a magic `loginUrl`. Guest upload is token-gated, 8MB, no quota.

### S3 — Cookie mutations have no Origin check

**Files:** `apps/web/app/api/posts/route.ts` and other cookie-auth POSTs; no CSRF helpers under `app/api/`

**What:** Supabase SSR cookies. Dev-login sets `sameSite: 'lax'`. No Origin allowlist on POSTs.

**Why it matters:** Lax cookies block most cross-site POST. Residual risk is cross-site form posts to same-site APIs.

**Fix (hypothesis):** Reject mutating methods unless `Origin` is an Evolved host. **Effort: M**
